0. Where this board sits in the NOVAZ80 project

The 6502 single-board computer: the CPU board for the "6502 SBC" configuration. On its own it is a complete minimal computer (W65C02S, 32 K RAM, 32 K ROM, W65C22 VIA). Its job in the project is to drive the Z80-style NOVAZ80 bus from a 6502, so the same I/O and VDP/sound boards work with either CPU.

The 6502 is memory-mapped and the NOVAZ80 peripherals are I/O-mapped. The board bridges the two by opening a 256-byte I/O window at 7F00–7FEF: an access there asserts bus IORQB, and the peripheral boards see the low address byte as a Z80 port number (section 5). The CPU runs at 1 MHz (4 MHz ÷ 4), while the undivided 4 MHz goes out as bus CLK, because the Zilog peripherals (and the I/O board's baud generator) need a fast bus clock (designer: this is the reason for the clock division).

This board is the +5 V source for the stack (DC-DC module onto SPEC pin 2). The programmer card (V102-PR1-2) burns its ROM in circuit.

Status: built and tested. VIA writes and Z80 PIO writes are known to work; there were problems with the Z80 CTC (section 4.10). Section 9 collects observations for the planned 4-layer revision.

4. Subsystems

4.1 CPU (IC1, W65C02S)

  • Address and data go straight to the memories, VIA and the stack. No bus buffers.
  • BE (bus enable) = bus BUSRQ (PROG pin 3, 1 k pull-up R12). This is how the board honours the programmer (section 4.9).
  • IRQB = bus INTB (CTRL pin 8, 1 k pull-up R6).
  • RDY and NMIB are tied straight to +5 V (no resistor). RDY is bidirectional on the W65C02S: the WAI instruction drives it low, which would short the output to +5 V. Software must not use WAI (section 9, item 4).
  • SOB is unconnected. A falling edge on it sets the V flag.
  • Outputs SYNC, VPB, MLB, PHI1O, PHI2O are unused. Pin 35 is NC.
  • D0–D7 have 4k7 pull-ups, so an undriven bus reads FFh.

4.2 ROM (IC2)

  • A0–A14 from the CPU. /CE = PLD ROMCSB (8000–FFFF, or programmer ROMCSX).
  • /OE = ROMOEX (PROG pin 7, 1 k pull-down → always enabled). /WE = ROMWEX (PROG pin 4, 1 k pull-up → the CPU can't write the EEPROM). Same arrangement as the Z80 SBC.
  • With /OE always active and /CE not gated by R/W, the ROM drives the data bus during any write to 8000–FFFF.

4.3 RAM (IC3) — unusual wiring

  • A0–A14 from the CPU.
  • /CS is tied to GND. /OE = PLD RAMCSB (address decode only). /WE = CPU R/W directly, not qualified by PHI2.
  • Consequences:
    • Every write cycle writes RAM, whatever the address. A write to 8000–FFFF also writes RAM at the address minus 8000h; a write to the I/O window or the VIA also writes RAM at the same 7Fxx address.
    • /WE follows R/W, which changes at the start of φ1 together with the address. So the write is "open" while the address is changing and before the CPU drives write data (data only becomes valid after PHI2 rises). The correct byte is written by the end of the cycle, but the previous address can be disturbed at the start of a write, and the end of the write relies on R/W rising no later than the address changes. Both are races (section 8).
    • RAM /OE is also active at 7FF0–7FFF. The PLD's RAM term only excludes the I/O window 7F00–7FEF, not the VIA's range (the source comment and the silkscreen "0000-7EFF" say otherwise). On a VIA read the RAM and the VIA both drive D0–D7.
    • Because every VIA write also writes the RAM at the same address, reading back a register that holds what was last written (DDR, ORx, ACR, PCR) gives the same value from both chips, so it looks right. Reads where the VIA's value differs (input pins, IFR, timer counters, shift register) fight. This fits "VIA writes were fine". To confirm on the scope.
  • RAM is permanently selected, so it never drops to standby current.

4.4 Address decode and bus translation (IC5 PLD)

The PLD makes the memory map and the only Z80-style strobe the board generates. Section 7 has the equations.

How the Z80-style CTRL group is produced:

CTRL pin Signal On this board
1 RSTB Diode-OR reset (4.7), driven
2 CLK X1 4 MHz, undivided, driven
3 M1B Tied to +5 V (never active)
4 MREQB Tied to +5 V (never active)
5 IORQB PLD: low while the address is 7F00–7FEF and PHI2 is high
6 RDB CPU R/W inverted by IC6B (low for the whole of every read cycle)
7 WRB CPU R/W directly (low for the whole of every write cycle)
8 INTB CPU IRQB input, wired-OR, 1 k pull-up
  • RDB and WRB are levels, not strobes. The timing edges come from IORQB, which only goes low during PHI2 high. Every peripheral board gates its selects with IORQB, so a bus access only happens inside the PHI2-high half of a 7F00–7FEF cycle.
  • MREQB high means no other board can see a memory cycle. That is fine, because no peripheral board decodes memory.
  • M1B high means the Zilog peripherals never see an interrupt acknowledge or a /M1-only reset (4.10).

4.5 VIA (IC4, W65C22S)

  • CS1 = +5 V, CS2B = PLD VIACSB (7FF0–7FFF, masked by ROMCSX). RS0–RS3 = A0–A3, so registers 0–F are at 7FF0–7FFF.
  • PHI2 = PHI, R/WB = CPU R/W, RESB = RSTB.
  • IRQB → D1 (1N5819, cathode at the VIA) → INTB. The W65C22S has a totem-pole IRQB output (the NMOS 6522 was open-drain), so the diode lets it share the wired-OR line with the open-drain Zilog parts (revision note 1).
  • Ports and handshakes go to J1 (6.2). CA1 and CA2 also go to bus AUX pins 1 and 2 (revision note 2).
  • CB1, CB2 are not connected.

4.6 Clock

  • X1 (4 MHz) → net CLK → bus CTRL pin 2 and IC8A clock.
  • IC8A toggles (D = /Q) → 2 MHz on its Q → clocks IC8B, which also toggles. IC8B /Q = PHI = 1 MHz, 50 % duty, to CPU PHI2, VIA PHI2 and PLD pin 1.
  • PHI2 rises about two flip-flop delays after a CLK rising edge, so PHI2 and bus CLK are synchronous. Each PHI2-high half contains two CLK rising edges, which the Zilog peripherals use to sample IORQB.
  • Both flip-flops have /R = RSTB and /S = +5 V. During reset Q = 0, so PHI is held high and the CPU clock stops (section 9, item 5).
  • The bus 4M line (SPEC pin 6) isn't connected on this board. In this configuration 4M is only driven by the VDP board's own oscillator, which is not synchronised to this board's CLK.
  • The I/O board's baud generator needs a bus CLK above about 3.7 MHz (I/O board document, section 4.4). At 4 MHz that's met, which is the point of the ÷4 arrangement.

4.7 Reset

  • MAX811L (IC7): /RESET (net RESB) low for at least 140 ms after power-up and on brown-out. /MR = net KBDRST (SPEC pin 8) and SW1, internal pull-up only.
  • Diode-OR onto RSTB: R7 (1 k) pulls RSTB up. D19 (cathode at RESB) pulls it low when the MAX811 asserts reset. D20 (cathode at IC6A output) pulls it low when RESX (PROG pin 6, 1 k pull-down R15) is high.
  • So RSTB is low when RESB is low or RESX is high, the same function as the Z80 SBC (PLD) and MTX board (NOR gates), done here with Schottky diodes. Low level ≈ 0.3–0.4 V (Schottky drop plus driver VOL), fine for HC/CMOS inputs.
  • RSTB drives the CPU RESB, VIA RESB, both 74HC74 /R pins and CTRL pin 1 (the stack reset: CTC/SIO on the I/O board, VDP).

4.8 Interrupts

  • One level-sensitive IRQB input fed by the wired-OR INTB: the VIA (through D1) and any open-drain Zilog device on other boards.
  • VDPINTB (SPEC pin 3) only passes through. VDP interrupts reach the CPU only through the I/O board's CTC channel 0, which has the acknowledge problem in 4.10. Without the I/O board, VDP status has to be polled.
  • IEO1 and IEO2 only pass through. Nothing on this board pulls IEO1 up (the Z80 SBC does). The daisy chain has no effect here because there is never an interrupt acknowledge.

4.9 Programming support

  • BUSRQ low → W65C02S BE low → the CPU three-states A0–A15, D0–D7 and R/W at once, mid-cycle. Unlike the Z80's /BUSRQ it doesn't stop the CPU: the 65C02 keeps executing (reading FFh from its own floating side), which doesn't matter because the programmer resets the target when it releases the bus. This answers the overview's question: the 6502 honours BUSRQ directly through BE, not through the PLD, and the release is immediate, so the programmer's fixed 200 ms wait is more than enough.
  • ROMCSX (PROG pin 5, 1 k pull-down R14) high → PLD forces ROMCSB low and masks RAMCSB and VIACSB.
  • IORQB is not masked by ROMCSX (the source comment says it is, the equation doesn't). The programmer drives image addresses 0000–7FFF, and image 7F00–7FEF (CPU FF00–FFEF, where 6502 vectors and handlers usually sit) is inside the I/O window. While it writes those bytes, IORQB pulses at the 1 MHz PHI2 rate, and RDB/WRB float (CPU R/W is three-stated and has no pull-up; IC6B's input floats with it). Peripheral boards can then see random I/O reads and writes at ports 00–EF: VDP registers/VRAM, sound, port C latch, CTC/SIO/PIO, OUT0. The final RESX reset clears most, but not VRAM, the SN76489 or the port C latch. See section 9, item 3.
  • RAM: /WE floats with R/W while /CS is grounded, so RAM contents are undefined after programming. RAM /OE is masked, so it doesn't fight the programmer's data.
  • Image: the 28C256's address 0 is CPU 8000, so code is assembled with ORG $8000 as a full 32 K image (vectors at image offset 7FFA–7FFF) and burnt from address 0, as the overview's toolchain section expects.

4.10 Working with the Zilog peripherals (I/O board)

The I/O board's PIO, CTC and SIO see a normal Z80 I/O cycle: IORQB low with RDB low (read) or high (write); the Zilog parts have no /WR pin and decide direction from /RD. M1B is always high. This explains what does and doesn't work:

  • Register writes and reads work in principle: IORQB is low for about 500 ns with two CLK rising edges inside it, comparable to a Z80 I/O cycle at 4 MHz. The designer reports PIO writes working.
  • No interrupt acknowledge. A Zilog device that raises /INT expects an INTA cycle (/M1 + /IORQ) to take its vector and later a RETI (ED 4D) fetch to clear its interrupt-under-service flag. Neither ever happens here. The 6502 sees IRQB low, but the device's interrupt request is not cleared by the acknowledge it is waiting for. Unless software clears it through the device's own registers, IRQB stays low and the 6502 re-enters its IRQ handler endlessly. This is the most likely cause of the CTC problems. To confirm: which register operations drop each part's /INT without an acknowledge (UM0081; for the CTC, a channel reset or disabling the channel interrupt), and whether the IO board CTC's VDP interrupt (channel 0) can be used this way at all.
  • No /M1 reset. The Z80 PIO has no reset pin and resets only on /M1 without /RD or /IORQ (or at power-up). On this board pressing reset doesn't reset the PIO, so software must reprogram it fully after every reset. CTC and SIO have /RESET pins on RSTB, so they are reset normally.
  • Write-data timing relative to IORQB is tight (section 8). Zilog parts sample on CLK edges well inside the strobe, so they are less exposed than the latches on the other boards.
  • If the CTC is used polled (no interrupts), its counters can still be read and its time-constant writes should work. The baud clock for the SIO needs only the 4 MHz bus CLK.

4.11 Power

  • PL1 centre pin = PWR, unswitched to PROG pin 8 (12 V on the bus, as on the Z80 SBC and MTX board).
  • The jack's sleeve and switch contact (net GIN) are not board GND. SW2 pole 2 connects them to PW1 pin 4 (G2). Only PW1 pin 1 is board GND. Same arrangement as the MTX board: the supply return passes through SW2 and the module's internal ground link.
  • SW2 pole 1 switches PWR → VIN (PW1 pin 3). PW1 pin 2 = +5 V.
  • Silkscreen "7VDC to 15VDC" and "+5VDC REGULATOR" (it's a buck module).
  • Bypass: three 1 µF caps for seven ICs plus the oscillator.
  • Copper: +5 V pour on F.Cu, GND pour on B.Cu.

  • Source comments that don't match the logic:
    • RAMCSB: "0000-7eff … with iorq and via not active". The equation only excludes the I/O window, so RAM /OE is also active at 7FF0–7FFF.
    • IORQB: "and external romcsx not active". The equation has no ROMCSX term.
    • Device line: "test this with g22v10 cos g20v8a doesnt work with protius".
  • RAMCSB uses all 8 product terms, so adding !VIA to it in this device means rewriting the RAM decode (e.g. !A15 & !(A14..A8 all 1) plus a term for 7F00–7FEF's complement) rather than adding a term. Check the term count before editing.

8. Timing notes

PHI2 = 1 MHz: cycle 1000 ns, φ1 (low) 500 ns, φ2 (high) 500 ns. W65C02S figures below are approximate 5 V values from the WDC datasheet: address and R/W valid ≤ ~30 ns after PHI2 falls (tADS), held ≥ ~10 ns (tAH); write data valid ≤ ~25–30 ns after PHI2 rises (tMDS), held ≥ ~10 ns after PHI2 falls (tDHW). Check against the current datasheet.

  • Memory reads: roughly 900 ns from address valid to data needed, minus the PLD (10 ns). A 150 ns 28C256 and a 100 ns 62256 have huge margin. The memory could run the CPU much faster; the 1 MHz limit comes from keeping the bus CLK at 4 MHz.
  • RAM writes (/WE = R/W, /CS grounded): at the start of a write cycle R/W falls while the address is still changing from the previous cycle, and the RAM writes whatever is on the bus (pull-ups or stale data) until the CPU drives data in φ2. At the end, R/W and the address change after the same ~10 ns hold. Both edges are races that the built board wins, but there's no designed margin. Standard fix: /WE low only while PHI2 is high and R/W is low.
  • IORQB start vs write data: IORQB falls about 10 ns (PLD) after PHI2 rises; write data is valid ~25–30 ns after PHI2 rises. Boards that clock a latch on the leading edge see stale data. This is the VDP board's sound latch (OUT6 rises at IORQB falling + its GAL delay, about 25–35 ns after PHI2 rises): a race. (Answers the VDP document's question about WRB timing: WRB is low for the whole cycle, so the edge comes from IORQB.)
  • IORQB end vs data hold: IORQB rises about 10 ns after PHI2 falls. Latches clocked by the trailing edge (I/O board port C, the TMS99xx /CSW, the MTX page register) clock another 15–25 ns later through their own GAL, i.e. 25–35 ns after PHI2 falls, but write data is only guaranteed for ~10 ns. It works because the data bus holds its level on capacitance (the 4k7 pull-ups take a few hundred ns to pull it high), not by design.
  • Zilog peripherals: IORQB low for ~500 ns contains two CLK rising edges, the first ~210 ns after IORQB falls (well after write data is valid). That should satisfy the Z84C20/C30/C40 sampling, comparable to a Z80 I/O cycle at 4 MHz.
  • VDP access spacing: 65C02 accesses to the window are at least 4 µs apart for back-to-back absolute stores (STA abs = 4 cycles), which meets the TMS99xxA's worst-case VRAM access spacing in most modes. Check the mode-specific figure in the data manual for tight loops.
  • Reset: the CPU clock is stopped high while RSTB is low (section 9, item 5).

9. Observations for the next revision

Most important first.

  1. RAM and VIA contend on VIA reads. RAM /OE is active at 7FF0–7FFF (4.3, 7). Fix: exclude the VIA range from RAMCSB (matching the silkscreen's 0000–7EFF).
  2. RAM wiring. /CS grounded, /OE from the address decode, /WE = raw R/W:
    • every write, at any address, also writes RAM (writes to ROM space corrupt RAM at address − 8000h);
    • /WE isn't qualified by PHI2, so writes are open during address changes (section 8);
    • the RAM never goes to standby.
    • Fix: RAM /CS = address decode, /OE = R/W-high (e.g. RDB), /WE = low only for PHI2 high and R/W low. This needs a gate or a PLD pin; the PLD has none spare (item 9).
  3. IORQB not masked during programming. Add !ROMCSX to the IORQB term (as the source comment intends). Also pull WRB/R/W up (about 10 k) so RDB/WRB don't float while BE is low. Without this, burning ROM bytes at image 7F00–7FEF (CPU FF00–FFEF) generates random I/O cycles on every peripheral board.
  4. RDY tied hard to +5 V. WAI drives RDY low on the W65C02S and would fight the rail. WDC recommends a pull-up resistor (a few k). Also put NMIB on a resistor so it can be used, and tie SOB high.
  5. CPU clock stopped during reset. The 74HC74s are cleared by RSTB, so PHI2 sits high while reset is held, and starts in the same instant RESB is released. The W65C02S datasheet asks for RESB low for at least two clock cycles. It works on the built board, but keep the divider running during reset (tie its /R pins high, or clear it only at power-up).
  6. No interrupt acknowledge for Zilog parts (4.10). Options for the next revision:
    • use the VIA for interrupts that need clearing in software, and wire VDPINTB to VIA CA1 (a jumper would do; CA1 is already on J1-33 and AUX1), so VDP frame interrupts reach the 6502 without the CTC;
    • or have the PLD generate a synthetic INTA (M1B + IORQB) on a read of a spare window address, and a RETI-equivalent, if vectored Zilog interrupts are wanted. Needs design work.
  7. I/O strobe timing. Qualify IORQB with a later, narrower sub-phase of PHI2 so it starts after write data is valid and ends before PHI2 falls. The ×4 clock makes this easy: IC8A's Q and CLK give four 250 ns phases per CPU cycle (e.g. strobe only in the third quarter, 250–375 ns into PHI2 high). This fixes both the sound latch and the trailing-edge latches (section 8).
  8. M1B/MREQB tied hard to +5 V on the bus. No resistor, so if anything else ever drives those lines (a second CPU board fitted by mistake, or the programmer in a later revision) it fights the rail. Use about 10 k pull-ups instead. A PLD-generated M1B would also let the Z80 PIO be reset (item 6).
  9. PLD full. All 22 pins of the ATF20V8B are used, and RAMCSB uses all 8 terms. Items 1–3 and 7 need R/W and a clock sub-phase as PLD inputs, so either an ATF22V10 (the source already mentions trying g22v10) or a narrower I/O decode (e.g. dropping A8/A9 from the window) would be needed.
  10. ROM drives the bus on writes to 8000–FFFF (/OE always on, /CE not gated by R/W). Same project-wide issue as the Z80 SBC and MTX board. With item 2's RAM fix, gating ROM /CE or /OE with R/W removes it.
  11. Floating inputs: VIA CB1/CB2 unconnected, and PA/PB/CA1/CA2 float when J1 and AUX are empty. Check whether the W65C22S has bus-hold or pull-ups on these pins; if not, tie them off.
  12. Almost no decoupling. Three 1 µF caps for seven ICs plus a 4 MHz oscillator. Add 100 nF at each IC.
  13. No bus buffering, as on the Z80 SBC (item 5 there). The 65C02 drives the whole stack directly; the W65C02S outputs are rated for light loads.
  14. Power input: same as the MTX board: 12 V on PROG pin 8 unswitched, no reverse-polarity, fuse or TVS, and the jack sleeve isn't board GND (return through SW2 and PW1). Check PW1's input rating against the silkscreen "7VDC to 15VDC".
  15. Data-bus convention: 4k7 pull-ups (FFh), as the Z80 SBC; the MTX board uses pull-downs. Pick one for all CPU boards.
